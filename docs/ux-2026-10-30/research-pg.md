Research date: 2026-10-30 (00:40 to 01:05 local). Scope: what PG players actually use for damage meters and combat logs, what they complain about, how each tool is set up, what the game itself offers (autopsy, combat-log settings with exact labels), what the repo already knows, and what "best in class" means for this specific community. ## 0. Headline findings (read these first)

1. **The exact in-game setting labels are now known from the client's string table and PGCombatTracker's screenshots, and the app's current copy is wrong on one of them.** Since the April 14, 2026 patch ("Move Chat Log settings from VIP to GUI", verified in the Steam news feed), **Save Chat Logs lives under Settings → GUI → Chat Logs** (the section sits at the bottom of the GUI tab; the game's client has the section keys `GUI_ChatLogs` and `GUI_ChatLogs_Stored_Location` and no longer has any `VIP_ChatLogs` string). **Combat Logging stays under Settings → V.I.P. → Combat Logging** (client keys `VIP_CombatLogging`, `VIP_CombatLogging_NotVIP`, `VIP_CombatLogging_Reminder`). The app, README and docs currently say "Settings → V.I.P. → Save Chat Logs" (`static/app.js:255`, `static/app.js:278`, `README.md:70`; `docs/ROADMAP.md:18-19` records that this is unverified and was set after the user's 27 Oct screenshot of the Combat Logging section, whose hint text says "Remember to enable 'Save Chat Logs' **above**", a sentence written for the pre-April layout). A one-minute in-game check settles it; the evidence points firmly at GUI.
2. **The "Log when…" dropdowns have exactly three options**, read from `Assembly-CSharp.dll` (`ui.settings.value.combatlogging.off` = "Off", `….chat.and.log` = "Chat Window (and log file if enabled)", `….log.only` = "Log File Only (if enabled)"). The natural mapping is 0 / 1 / 2, which matches the file values on this Mac (all 2 = "Log File Only (if enabled)", the value shown in PGCombatTracker's screenshot). **Inferred, to confirm in game:** level 1 also writes to the file, it merely shows the lines in chat as well. If so, the app's health check that treats `combatLog_* == 1` as "reduced, the DPS meter may miss hits" (`server.py:3486-3490`, `DESIGN.md:655`) is too strict, and the fix copy at `static/app.js:261` ("every 'Log when…' row on a Log File option") should accept either non-Off option.
3. **`VIP_CombatLogging` in `GorgonSettings.txt` is almost certainly a section-expanded flag, not an on/off switch.** Every sibling (`VIP_Benefits 1`, `VIP_SpecialReports 1`, `VIP_Reports 1`, `VIP_BookMode 1`, `VIP_ChatLogs 0`, `GUI_Chat 1`, `GUI_Other 1`, `GUI_Sizing 1`, `GUI_DiscordIntegration 1`) is a section header name from the client string table, and the client lists `VIP_CombatLogging` alongside `VIP_CombatLogging_Reminder` (the hint text) and `VIP_CombatLogging_NotVIP`. The app's check `settings.get("VIP_CombatLogging") == 1` (`server.py:3467`, `3471-3479`) would therefore report "Combat logging is off (VIP_CombatLogging 0)" to a player who merely collapsed the section. The real switches are the seven `combatLog_*` levels plus `LogNonAttacks`. Inferred; cheap to verify by collapsing the section in game and re-reading the file.
4. **Nobody in this community has a party damage meter, and the game is designed so that nobody can build one from a single log.** Every community tool (PGCombatTracker, Kaeus's Combat Tracker, Project Gorgon MultiTool, Peteskis's viewer, gorgon-notes) reads the same `[Combat]` chat-log lines, which only ever contain the log owner's and their pets' hits (`docs/DPS-FEASIBILITY.md:50`, confirmed with a friend's log at `:191`). The game's own answer to "who did how much" is the **Pathology autopsy report**, which the developer explicitly designed in 2011 as the in-game replacement for a damage meter and which is still not written to any file on Mac (`docs/DPS-FEASIBILITY.md:147-160`). The 21 Oct 2026 Halloween update's "Remove excessive client logging to Player.log" made the Windows `ProcessTalkScreen` route dead too (glogger's own TODO, verified 2026-10-26: zero `LocalPlayer:` lines after the patch). **Gorgon Notes' room/everyone feed is therefore the only party meter that exists for this game.** The competition is not another meter; it is "no meter, read the autopsy".
5. **"Zero setup" for a party meter is bounded by three unavoidable steps per player, and everything else can be removed.** Unavoidable: (a) VIP (the client has a `VIP_CombatLogging_NotVIP` string, and every tool README says combat lines need VIP; unverified whether a non-VIP log really has none), (b) Save Chat Logs on, (c) every "Log when…" row not Off. Removable: the party code (the everyone feed already removed it), the folder picker (the app finds the folder per OS), the character name (the login line names it), pet lists (behaviour heuristic), the "Start session" step (area-based runs exist), Discord webhook pasting (Connect Discord exists). The remaining UX job is to make (a)-(c) a single guided screen with live confirmation ("we see combat lines: yes/no"), which no other PG tool does.
6. **The community is tiny and the tools are hobby-grade; the bar for "best in class" is low in features and high in trust.** Star counts: GorgonSurveyTracker 15, glogger 7, PGCombatTracker 6 (233 downloads of its last release, March 2025), MultiTool 3 (33 downloads), Kaeus's tools 0, Peteskis 2. Only glogger is actively maintained (v1.7.0 released 29 Oct 2026). The things players complain about in issues are basic: a window that cannot be resized, a folder picker that fails in Firefox, "baby spiders don't count as DPS", a tool that broke after a patch. The developer has said in 2011 that providing text for third-party tools "seems like a weird relic from bygone text-MUD days" and in 2021 that the combat log is "being provided as a way for 3rd-party tools to generate new kinds of reports"; the Oct 2026 notes call log-reading overlays "the first legal 'add ons'". So: a polite, read-only, never-touches-the-client tool is welcome; anything that looks like automation is not.

## 3. What the game itself offers (verified, with exact labels)

### 3.1 The settings window (labels verified from PGCombatTracker's screenshots plus the client's string table on this Mac, `Assembly-CSharp.dll` dated 27 Oct 2026)

**Tabs** (screenshot, left rail): System, Keys, Controls, Graphics, GUI, Sound, V.I.P., Special. The gear icon at the bottom of the right-hand sidebar opens it.

**Chat Logs section** (key `GUI_ChatLogs`; moved from the V.I.P. tab to the **GUI tab** on 14 Apr 2026):
- "Save Chat Logs" [checkbox] "Enabled" (settings key `LogChat`; tooltip string "Should chat text be saved to a text file on your hard drive?")
- "Saved chat logs will be stored here:" `<path>/ChatLogs/` with an **Open Folder** button (key `GUI_ChatLogs_Stored_Location`). The path shown on Windows is `C:/Users/<you>/AppData/LocalLow/Elder Game/Project Gorgon/ChatLogs/`.
- Evidence for GUI: Steam news 2026-04-14 "Move Chat Log settings from VIP to GUI" (verified from `dl/steamnews.json`); glogger README step 2 "Go to GUI, scroll to the bottom, and turn on the chat logging"; GorgonSurveyTracker README "Game Settings, under the GUI category … 'Save Chat Logs' under the Chat Logs section (located at the very bottom)"; the client string table lists `GUI_ChatLogs` and `GUI_ChatLogs_Stored_Location` among the GUI section keys and contains no `VIP_ChatLogs`; this Mac's `GorgonSettings.txt` carries `GUI_ChatLogs 1` (expanded) and a stale `VIP_ChatLogs 0`.
- Evidence for V.I.P.: only PGCombatTracker's screenshot, taken before April 2026 (its last commit is May 2026 but the README text and screenshot predate the move), and the hint sentence under Combat Logging, which still says "above".

**Combat Logging section** (key `VIP_CombatLogging`, **V.I.P. tab**; a `VIP_CombatLogging_NotVIP` string exists, so the section shows a not-a-VIP notice to non-subscribers):
- Hint (key `VIP_CombatLogging_Reminder`): "Remember to enable 'Save Chat Logs' above if you want your combat logs to be written to a file!"
- Seven dropdown rows, label → settings key → tooltip:
  - "Log when I attack enemies" → `combatLog_MeAttackEnemy` → "How should we record damage dealt to enemies?"
  - "Log when my pets attack enemies" → `combatLog_PetAttackEnemy` → "How should we record pet damage dealt to enemies?"
  - "Log when my enemies attack me" → `combatLog_EnemyAttackMe` → "How should we record damage dealt to us?"
  - "Log when my enemies attack my pets" → `combatLog_EnemyAttackPet` → "How should we record damage dealt to our pets?"
  - "Log when I am healed or take indirect damage" → `combatLog_MeIndirectlyDamaged` → "How should we record healing and damage-over-time done to us?"
  - "Log when my pet is healed or takes indirect damage" → `combatLog_PetIndirectlyDamaged`
  - "Log when my others are healed or takes indirect damage" (sic, the game's own typo) → `combatLog_EnemyIndirectlyDamaged` → "How should we record healing and damage-over-time done to enemies and nearby allies?"
- Each dropdown has three options (string keys in the client, in this order): **"Off"**, **"Chat Window (and log file if enabled)"**, **"Log File Only (if enabled)"**. File values seen: 2 on every row here with "Log File Only (if enabled)" selected in PGCombatTracker's screenshot. Inferred mapping 0 / 1 / 2. The option names say that both non-Off options write to the file when Save Chat Logs is on; "Log File Only" merely keeps the spam out of the chat window.
- "Log non-damaging abilities" [checkbox] "Enabled" → `LogNonAttacks`.

**Special Reports section** (V.I.P. tab, keys `VIP_Reports_*`): "Export Character as JSON", "Export Storage as JSON" (and CSV), a stored-location line, and since 21 Oct 2026 a checkbox "Automatically Export on Logout" (`AutoExportCharacterOnLogout`), which per the Halloween notes "automatically save[s] the current character whenever you log out or switch areas" and whose report now includes per-NPC raw favor, councils spent, vendor reset time and notes (the 27 Oct bugfix patch fixed a crash "if you had the VIP auto-save-report checkbox enabled").

**Book mode** (V.I.P. tab, `VIP_BookMode`, `BookSaveToFile`): "Should long-form text (such as books) have a button to save the text to a file?"

**Discord Integration** (GUI tab, `GUI_DiscordIntegration`, `GUI_JoinDiscord_Label`): a section exists; the 7 Jul 2026 notes mention "the discord activity feed". What it does was not found (probably Rich Presence / join link); it is not a posting channel for tools.

### 3.2 Is VIP needed for `[Combat]` lines?
- 2021 launch text (wiki, "All About the VIP Membership Program", May 2021): the VIP "Combat Log … records every hit your character takes or deals to others in a text file. This text file is too verbose ('spammy') to be useful to most players, but it's being provided as a way for 3rd-party tools to generate new kinds of reports." and "These reports are actually available to all players right now … then they'll become VIP-members-only."
- Every tool README written since says VIP is required (PGCombatTracker: "VIP subscription for Project Gorgon is required for ChatLogs to contain Combat lines"; MultiTool; PG-Alerts "to my knowledge"; PickupNotifier "VIP required for chat log access").
- The client has a `VIP_CombatLogging_NotVIP` string, i.e. the section renders differently for non-VIPs. **Still unverified** whether a non-VIP who had logging on keeps getting lines; the wiki's VIP page (edited 11 Sep 2026) lists only "Access to special in-game reports, such as a 'character sheet'" and never mentions chat or combat logs, so chat logging itself may have stayed free (Citan in 2021: "still weighing the pros and cons of changing something that players have already gotten used to having for free"). The test remains: a non-VIP friend's log.

### 3.3 The autopsy ("Detailed Analysis")
- Design intent, verbatim from Citan's Dec 17, 2011 Elder Game post "Field Autopsies, and Man I'm Slow" (wiki mirror): players want "to see how much damage they did, who killed the monster, what their DPS was", and "I'll answer those questions in a gamey way with the Pathology skill." Tiers: cause of death and killer at basic success; "you'll also get a little report of how much damage each player did to the monster" at higher skill; "If you're really good at Pathology, you can see how much armor damage each person did to it." "if you botch the autopsy, the corpse is ruined." "only one player can autopsy a given corpse. Afterward, anyone can view the report." On parsing: a scrolling combat text "so that third-party tools can analyze the text … seems like a weird relic from bygone text-MUD days."
- Wiki Pathology page: "examine corpses to see the player who killed it and the cause of death. Higher skill allows more details to be determined"; kits Autopsy Kit (Toolcrafting 15; sold by Mushroom Jack, Glajur, Amutasa, Mox Warcut), Forensic Inspection Kit (+3), Forensic Analysis Kit (+5), Carbon-form Scrutinizer Array (+10), Enchanted Autopsy Kit. Anatomy sub-skill for the mob type affects success.
- The phrase "Detailed Analysis" is not on the wiki or in the client's string table (searched); it is what the user's 26 Oct in-game report was called (`docs/DPS-FEASIBILITY.md:176`). Numeric Pathology thresholds for the damage tiers are not documented anywhere found. The user, at Pathology 51, botched 461 of 461 autopsies in 30 days (`docs/DPS-FEASIBILITY.md:168`) and then got one success on 26 Oct.
- Where the report goes: the corpse's talk window only. On Windows it used to echo into `Player.log` as `ProcessTalkScreen(<id>, "Search Corpse of X", "<death details>", …, Corpse)` (glogger `docs/architecture/player-log-events.md:1170-1184`); the 21 Oct patch removed it for everyone (glogger `docs/TODO.md:21-24`, verified against a live game dir). The Mac never had it. **So the autopsy is UI-only now for every platform**, and the "glogger fork with DPS" the user's friends mentioned (`docs/DPS-FEASIBILITY.md:161`) is dead by the same patch; no fork with DPS code exists on GitHub (code search for "dps" in Glogger-Team, crisp-oddio, lazyassadmin, Aestiel42: zero hits outside the README sentence).

### 3.4 Official stance on tools (for the app's tone and limits)
- Halloween Update, 21 Oct 2026 (Steam news, verbatim): "The first legal 'add ons' for the game were designed to make this system less painful to players. (A reminder that altering the game client is against the terms of service; these add-ons read log files and have a window that overlays the game client window; they don't change the running game in any way.)" and "not to 'break' these third-party surveying tools (they will still work, although they may need revising due to changes in player logging)."
- The same note: "Remove excessive client logging to Player.log".
- 2017 forum consensus (search snippet): "External tools of informational nature exist and are encouraged, while automation tools are banned."
- Takeaway: a log-reading overlay/companion is explicitly sanctioned; Gorgon Notes can say so in its onboarding ("reads files the game writes; never touches the game").

## 4. The 21 Oct 2026 patch, consequences for every tool

- `Player.log` now carries no `LocalPlayer: Process…` events on any platform (glogger TODO: "live Player.log (24MB) and Player-prev.log … contain zero `LocalPlayer:` lines … The 10/21 update's 'remove excessive client logging to Player.log' removed the verbose player events, not just noise"). glogger reacted within days by moving to chat-log signals ("chat level-up lines … are the only live absolute skill signal since ProcessUpdateSkill went away post-10/21", PR #40) and to auto-importing VIP reports; Kaeus's vendor tracker broke (#8, #9).
- The chat log is untouched (glogger: "Chat.log is healthy (999 [Status] + 9,510 [Combat] lines today)"; this Mac's `Chat-26-10-30.log` has 6,965 `[Combat]` lines at 00:50).
- Net: the whole community's live-data surface collapsed to the chat log plus the new auto-export-on-logout/zone-change report. Gorgon Notes already lives there, and its `docs/GLOGGER-COMPARISON.md:7` "Key finding" (Mac lacks LocalPlayer lines) is now true of Windows too, which closes the "install glogger's dmg and compare" test for good and can be recorded as such.

## 5. What "best in class" means for this community

Industry leaders (Details! for WoW, ACT/FFLogs for FFXIV, arcdps for GW2) share three properties: zero configuration after install, the party appears automatically because the game's log contains everyone, and the result is shareable in one click. Project: Gorgon removes the second property by design. So "best in class for PG" is:

1. **Setup that proves itself.** No PG tool tells the player whether logging is actually producing combat lines. The best possible first screen is a three-row checklist that the app fills in live from files it already reads: Chat log file exists and grew in the last minute (`ChatLogs/Chat-YY-MM-DD.log` mtime), combat lines seen today (count), every "Log when…" row not Off (from `GorgonSettings.txt` `combatLog_*` > 0). Each row names the exact label and tab (§3.1) and the one click to fix. The app already has the health model (`/api/health`, `static/app.js:255-278`); the gap is wording (GUI vs V.I.P.), the level-1 rule, the `VIP_CombatLogging` misread, and making it the Combat view's first-run state rather than a margin item.
2. **No folder picker, no character name, no pet list.** Already true of Gorgon Notes; Kaeus and PGCombatTracker both ask. Keep it and say so ("found your log, found Robchew, found Cardi Bee").
3. **Party without a code.** The everyone feed already does this; the Party window's code flow is now the advanced path, not the default. The remaining honest limit is attribution when two parties share a cave, for which the planned "I was not in this group" edit is the right fix (`docs/ROADMAP.md`, "Next step (user)").
4. **One honest number per player, in the game's own units.** The autopsy lists health and armor separately per attacker and is the only ground truth players trust; the app's per-enemy table already mirrors it (`docs/DPS-FEASIBILITY.md:174-191`). Lead with "matches the autopsy" language; no other tool can claim it.
5. **Share where the group already talks.** Discord. Connect Discord is built; the everyone page is a link. PG Emissary is the precedent for Discord as the community's notification bus.
6. **Visible "still working after the patch" status.** Players have just watched glogger's and Kaeus's features die on 21 Oct. A dated "reads the chat log, which the 21 Oct update did not change" line is worth more than any chart.
7. **Read-only, overlay-friendly, no client changes**, stated in the words of the Halloween notes.

Features the other tools have that Gorgon Notes does not: PGCombatTracker's user-placed **time markers** ("placing markers before and after a dungeon run": the app's Start/Stop session covers it), **heals tracked** (the `Recovered:` lines are parsed but not surfaced as a heal meter), **image export of a chart** (the app has a PNG table card for Discord), MultiTool's **in-game DPS overlay** (the Mac HUD panel is still on the roadmap; note PickupNotifier's warning that exclusive fullscreen blocks overlays), Kaeus's **ability icons from the CDN** on the bars, and glogger's **setup wizard**.

## 6. What players would need to do for a party meter with zero setup (the irreducible list)

Per player, once:
1. Have VIP (probably; §3.2). Nothing a tool can remove; the app can detect the symptom (chat log grows, zero `[Combat]` lines all session) and say "the game writes combat lines for VIP accounts; without VIP the meter has nothing to read" instead of a generic "turn on combat logging".
2. Settings → GUI → Chat Logs → Save Chat Logs: Enabled. (Verify the tab in game once; §3.1.)
3. Settings → V.I.P. → Combat Logging: every "Log when…" row on "Log File Only (if enabled)" (or the chat-window option), "Log non-damaging abilities" Enabled. The two "pets" rows matter for pet classes; "my enemies attack me" for deaths; "my others are healed or takes indirect damage" for DoT ticks (the app's DoT rule depends on it).
4. Install Gorgon Notes and leave it running. Everything else (folder, name, pets, fights, runs, upload to the everyone feed, Discord) is automatic today.

Per session: nothing, if the everyone page is the meter. A party code only when two groups share an area and want separate tables.

What cannot be removed by any client-side design: another player who does not run the app will never appear with numbers (only as a name in the roster); the autopsy is the only way to see a non-user's damage, and it is UI-only since 21 Oct.
