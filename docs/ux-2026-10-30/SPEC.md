### 2.1 The Setup window (one component, used by Session, Combat, Vendors, Storage, Character)
Contract (A-FINAL §1 verbatim for copy and sub-states; this section is the interface the packages code against):

```js
// P2 defines; P4 (Combat) and the view renderers call. P0 declares the globals.
const NEEDS = { session: ['chat-log'], combat: ['chat-log', 'combat-logging', 'combat-lines'],
                vendors: ['character-export'], storage: ['storage-export'], character: ['character-export'] };
let setupShowing = null;      // the view whose Setup window is rendered right now, else null (P0 declares)
let plaqueInView = null;      // exists today (app.js:468); renderSetup sets it to the row's fixKey
function setupNeeded(view)    // A §1.1 with the §2.8.2 amendment for combat-lines
function setupLists(src)      // true when setupShowing's NEEDS list holds src (margin pointer, no second plaque)

function setupCounts()        // { done, total: 4, undone: [...] } over chat-log, combat-logging, character-export, storage-export (P0 defines; About uses)
```
`renderSetup(view)` owns the title row (finding + stamp per A §1.4) whenever it returns `'replace'`; every other `.win` in `#v-<view>` gets `hidden` and the renderer returns at once. `'above'` (Combat only, `c.totals.fights > 0`): the window sits first and the renderer continues. `null`: `#w-<k>-setup` is `hidden`, `setupShowing = null`. Ids `w-s-setup`, `w-d-setup`, `w-v-setup`, `w-t-setup`, `w-c-setup`, each a `.win` with a centred `primary` title bar "Setup <span class="count">0 of 1 done</span>" placed first in the view's `.main-col` (after the follow note on Session and Combat). Hidden windows are the *generic* rule `$$('#v-<view> .win:not(#w-<k>-setup)').forEach(w => w.hidden = true)`, so no renderer hides windows one by one. Rows, states, steps, plaque copy, the closing line, footers: A §1.2 to §1.4. Never on Teleports, Statehelm, Files. Re-entry `#<view>?setup=1` (A §1.1). Loading guard: `setupNeeded` is false while `S.loading && !S.healthAt`.
