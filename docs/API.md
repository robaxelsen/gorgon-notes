# Gorgon Notes: HTTP API

Everything the page talks to, served by `server.py` on `127.0.0.1:8787`. Field shapes and the reasoning behind each contract are in `DESIGN.md` → Server contract. Every `POST` needs `Content-Type: application/json` and, when the browser sends one, this server's own `Origin`; the server only listens on localhost.

| Endpoint | Returns |
|---|---|
| `GET /api/session?scope=day\|login&character=` | XP per skill, XP/hr, level-ups, loot, areas, deaths and kills (`combat`, `combat31d`, `death` events), councils in and out (`councils`: received incl. coins looted or given, casino wins as `gaming`, stolen, recovered, net, events, the on-hand balance from the selected character's export; spending is never logged) from the newest chat log |
| `GET /api/tail?log=&offset=` | New chat lines since `offset` (UI polls every 2 s) |
| `GET /api/reports` | All files in `Reports/` with type/character/timestamp |
| `GET /api/report?file=` | One raw report JSON (path-traversal guarded) |
| `GET /api/vendors` | Per-NPC vendor cap, councils spent, remaining, reset time, next tier |
| `GET /api/storage` | Per-vault used / capacity / free, value, next favor tier |
| `GET /api/plan?character=` | The sell plan for the inventory (the Sell window in Vendors): books, documents and scrolls get a vendor and an about-price (the character export's sale multiplier), gear is listed as the player's call with its price, everything else is kept (nothing is trash by default; a Sell / Keep mark per item type overrides, `POST /api/mark`), grouped into vendor stops by area; `{"error": "no items export"}` when there is none |
| `GET /api/consolidation?character=` | Split stacks across vaults from the newest storage export: slots back by merging, destination per item, pickup plan by area; `{"error": "no items export"}` when there is none |
| `POST /api/mark` `{typeId, mark}` | The keep list for the Sell plan: `sell` / `store` per item type (`store` is the Keep mark, the value name kept for older files; `null` removes), saved in `marks.json` beside `capacity.json` |
| `POST /api/capacity` `{vault, slots}` | Save (or clear with `null`) a manual vault size; `400 {error}` unless `slots` is a whole number 1 to 999; `403` unless the body is `application/json` from the app's own origin |
| `GET /api/health?character=` | `app` (this copy's version from `build.txt` or the git tag, the newest GitHub release, `newer`), one data-health verdict per source (exports, chat log, settings, combat lines, alts, VIP, game data, the everyone feed, the private room), game state, reminder moments; activity since an export counts only lines while that character was logged in (`activityThresholds`: 1 storage search, 50 loot stacks). Health rows changed 30 Oct (DESIGN.md → Data health → Severity rules): a **bad `chat-log`** lists `session, combat, statehelm, files` in `views` (the export views never needed a log) and carries `evidenceData { looked, exists, logChat, settingsSavedAt, readable, short }` (`short` is the evidence without the "Looked in …" sentence); **`combat-logging`** is ok ("Every \"Log when…\" row is on, and so is Log non-damaging abilities.", `views []`) or **warn** on `combat` when any "Log when…" row is Off or Log non-damaging abilities is off, named by the game's labels, `evidenceData { off (sorted keys), logNonAttacks, vipCombatLogging }`; provisional and unverified (30 Oct): a `combatLog_*` row at 1 counts as writing the file, and `VIP_CombatLogging` is reported but never read (most likely the section's collapsed flag); new **`combat-lines`** ("Combat lines", server only, `views ["combat"]`): ok "First combat line 18:44 · 6,965 so far today." with `at` = that line, info "No combat line yet today. The log holds 1,204 lines.", or warn with `fixKey "combat-logging"` after 20 min and 200 lines since the login with no `[Combat]` line while every Combat Logging row is on ("… The game writes combat lines for VIP accounts; if you have VIP, check the Combat Logging rows above."), `evidenceData { combatLines, firstCombatAt, lines, sinceLogin, loggedInMin }`; **`everyone-feed`** is ok "131 fights sent today, last 00:28." (`views []`), info "Sending is off; nothing of yours goes to everyone's fights." (`views []`) or warn when the feed stopped taking fights and some wait, `evidenceData { on, available, posted, pending, lastPostAt }`; **`party-sharing`** (only while a code is joined) is ok "Room gn-…, last message 00:39, 360 fights sent." (no roster tail: the Your party rows say who is sharing) or warn "The private room hasn't answered since 20:14; …", `evidenceData { code, pending, sent }`. `views[]` of a **never-seen export** (bad, `at` null) names only the views whose Setup window asks for it: `character-export` → `vendors, character, files`, `storage-export` → `storage, statehelm, files`; never the cross-view consumers (Storage for the character export, Vendors for the storage export). Once the export exists, ok or stale, the lists are the fuller ones (`character-export` + `storage, statehelm`; `storage-export` + `vendors` while not ok). **`vip`** with no export at all is ok, `at` null: "No export yet, so VIP can't be told. The VIP menu's Export buttons prove it." The `character` falls back to the newest character export's when no recent log holds a "Logged In As" line (a log rolled at midnight, a fresh install), so that export's own verdicts match it |
| `GET /api/icons?names=&typeIds=&types=` | CDN icon IDs for item names, storage TypeIDs and vendor item types |
| `GET /api/lookup?quests=&powers=&item=` | Readable quest names and item power text from game data; `item=` resolves an item name fragment to the vendor type words its items carry (`{query, items, examples, types: [{type, items}]}`, the Vendors search) |
| `GET /api/teleports?refresh=1` | Every Teleportation Machine code (Teleports tab), parsed from the wiki's player-kept list (`wiki.projectgorgon.com/wiki/Teleportation_Machine`, read as wikitext through the MediaWiki API with a User-Agent): `zones[] { zone, note, landmarks[] { name, codes[], note } }`, `counts`, `revid`, `confirmedAsOf` (the page's "confirmed as of" date as `YYYY-MM-DD`, or its raw words, or null), `fetchedAt`, `source`, `stale` (the copy is over a day old), `error` (null, or why the wiki didn't answer while the cached copy is shown). Cached with the raw wikitext in `cache/wiki/teleport-codes.json`, re-fetched at most once a day or on `refresh=1`; no cache and no wiki → `{ error, zones: [] }` |
| `GET /api/statehelm?character=`, `POST /api/statehelm` `{picked: [npc keys]}` / `{npc, count}` | The Statehelm tab: every Statehelm NPC with a Training service (`trainers[] { npc, name, desc, skills[] (readable, skills.json), unlocks[], prefs[] { desire, name, keywords[], pref, favor }, picked, favor, favorPoints, met, notes, prodigyAt, prodigyReady, items[] { name, typeId, rarity, where, stack, value, icon, desire, pref } (the newest storage export's items that match a Love / Like preference: keywords, `MinRarity:`, `SkillPrereq:`, `!Keyword`), unchecked[] (preference names with `Special:` keywords the export can't judge), gifts { given, left, cap, logged, manual, quests, times[] } }`), `picked[]`, `cap` (5), `week { start, end, rule, tz, logs[] }` (Monday 00:00 US Eastern as local ISO times, the rule as words, `America/New_York`, the chat logs read), `sources { character, storage }`, `cdnVersion`. `logged` counts `[Status] You gained N favor with <trainer>` lines since the week started, on the selected character's logins, while the last `Entering Area` was Statehelm or Under Statehelm, and leaves out a line whose second also has an `added to inventory` line (a quest turn-in). `POST {picked}` replaces the tracked trainers (`400` for a key that is not a Statehelm trainer); `POST {npc, count}` sets this week's count by hand (0 to 99, `null` goes back to the log count; older weeks are dropped); both answer with the `GET` shape plus `ok`. Picks and counts live in `settings.json` under `statehelm`. |
| `GET /api/files` | Every file the app knows (Files tab): exports in `Reports/` with their head fields, `partial` / `newest` / `source` flags and a `valid: false` + `error` line for a file that won't parse, `capacity.json` (listed even when absent), every cached CDN file (`cdn/v<ver>/<name>.json`) and every chat log (`logs/Chat-YY-MM-DD.log`, newest first, the newest flagged `newest` with the DPS meter's `combatLines` / `lastLineAt` / `lastCombatAt`), each with `bytes`, `mtime`, `mtimeNs`; `csvSkipped` counts the CSV twins (never served) |
| `GET /api/file/node?id=&path=&offset=&limit=&depth=&maxNodes=&mtime=&locate=` | One node of a file by RFC 6901 pointer: a page of children (200, max 1,000; `depth` > 1 fills breadth-first up to `maxNodes`, 2,000 default) or a scalar's full value; `total` node count on the root; `locate=1` adds `pos`; cross-file `link`s into cached game data; `409` when `mtime` no longer matches, `422 {line, col, msg}` for invalid JSON, `404 {"error": "no such path"}` |
| `GET /api/file/search?id=&q=&limit=&mtime=` | Case-insensitive substring over keys and values of one file: hits in document order with `path`, `where`, `snippet`, `pos`; `total` up to 10,000, `capped`, `partial` after a 2 s budget; `q` under 2 characters is `400` |
| `GET /api/file/lines?id=&offset=&limit=&q=&mtime=` | A page of a chat log's lines (`{n, ts, msg}`, default the newest 500, `limit` up to 2,000, `total`, `more`) or, with `q`, every line containing it (file order, up to `limit`, `matches` counted to 10,000, `capped`); `logs/` ids only, `400` for anything else |
| `GET /api/file/raw?id=&path=&mtime=` | The whole file streamed from disk (never parsed, `Content-Disposition: inline`, `nosniff`; `text/plain` for a chat log) or one subtree pretty-printed (`413` over 1 MB) |
| (the Worker) | `cloud/`: the Cloudflare Worker behind everyone's fights (`/everyone/fights`, `/everyone/tick`, `/everyone/live`, the `/everyone` page), the Private room (one Durable Object per code, `/room/<code>/*`, since 26 Oct) and the Discord connect broker (`cloud/README.md`); ntfy.sh is the code room's fallback. `PG_ROOM` overrides the URL, empty turns it off. `tools/fake-room.py <port> <seed.json>` stands in for it in a test harness |
| `GET /api/settings`, `POST /api/settings` `{discordWebhook}` | The Discord channel for "Post this run to Discord" and "Post fight to Discord", kept in `settings.json` beside `capacity.json`, shown back with its token hidden; `connected` says it came through Connect Discord, `pending` that a Connect is waiting. The UI only ever posts `null` (Remove); a URL is still accepted for scripts |
| `POST /api/discord/connect` `{}` / `{cancel:true}` | Connect Discord: answers the Worker's `/discord/start` URL to open in a browser (Discord's own server + channel picker); the server then claims the webhook from the room within 10 minutes (`docs/DISCORD.md`) |
| `POST /api/settings` `{shareEveryone: bool}` | Turn the everyone feed off or on (every closed fight of the day goes to everyone's fights, `<room>/everyone`, by default, no party code needed; it is also what Your party reads, so Stop sending stops the read and the live ticks too); answers `everyone` as `/api/party` does |
| `POST /api/discord` `{fight}` / `{party}` / `{session}` | Post a fight (its id), a merged party fight or a party session (`sessions[].id` from `/api/party`: manual Start/Stop, or an automatic run in one area) to the webhook as an embed: a table of players and pets (health, armor, damage, per second, share, kills) as a code block (four columns, in every post), a few facts, and a PNG of the full table when the page drew one (`preview: true` answers the card for the page to draw, then `image` carries the PNG) |
| `GET /api/party`, `POST /api/party` `{action: "new"}` / `{code}` / `{code: null}` / `{paste}` / `{session: "start" or "stop" or "forget"}` | Your party (`docs/SHARING.md`). Since 30 Oct the fights come from the everyone feed with no code: `source` `"everyone"` (the feed, read every 10 s while a view watches, 2 s while someone fights), `"room"` (a code joined; the room's rows merge in and win on a clash) or `"none"` (sending off, no code); `fights` = this copy's whole day of closed fights merged with the received rows that belong to it (`party_mine`: the poster is in the chat log's hunting-party roster, or names you in its `party`, or, in a party, fought in your area overlapping one of your fights, tagged `nearby`); each member carries `via` `local` / `feed` / `room` / `paste`. `feed { readAt, error, errorAt, rows, members[{who, lastSeen, app}] }`; `roster { inParty, name, members[], leader, log, notSharing[], unnamed, sharing[], status{name: you | sharing | too-old | not-running}, apps{name: app} }` (sharing = a fight row in 24 h or a live tick; too-old only from a joined room's members below v0.11.0); `invite { repo }`; `area` (the newest fight's, else the zone); `live[]` = the roster's ticks and yours (with an unnamed party: the same area within 20 s of your open fight). Still there: the code, the link's health (`ntfy`, `transport`), `sessions`, `members`, `roomMembers`, `discord`, `everyone`; `party.json` beside `capacity.json` holds the code, the manual sessions and what was posted, nothing of the feed read |
| `GET /api/combat?scope=day\|login` | Personal DPS meter from the newest chat log's `[Combat]` lines, read incrementally: fights (15 s damage gap), you vs pets, per-ability rows, damage taken, kills, deaths, kill mechanics, unattributed indirect damage, a per-second timeline per fight, damage over time credited after your first hit (`dotMe`, `dotPet`), an attacker × enemy split (`byTarget`, `ticks`, the top 40 enemies by credit, `byTargetMore` the count you hit that are left out; damage-over-time shares are whole numbers that sum to the enemy's ticks exactly; the Breakdown's By enemy table is derived from them client-side), a live "now" figure; `since` (where the scope starts, local ISO), `carried` (fights before this log's first line that count: the run in progress at midnight, when the game starts a new log; the server feeds the previous day's log into a new tracker first, so the area, the character and the party carry over, and the day scope starts at the first fight of a chain at most 15 min apart that reaches into this log), `seededFrom` (that log's name, or null); `{}` with no chat log |
| `GET /api/zone?area=&character=` | Current zone panel: NPCs in the area (default: current area from the chat log) with favor, vendor councils left, storage, services, gift loves, notes; zone totals; adjacent areas with councils/slots; `matched: false` for a chat area name game data doesn't know, `guessed: true` for the shared short names Caves / Dungeon / Home |

Additive fields (old clients ignore them): `/api/session` gains `loggedIn`, `loggedInAt`, `loggedOutAt`, `lastLineAt`, `playing`, `events[]` (incl. `death` events), `channels{}`, `combat`, `combat31d`, `councils`; `/api/vendors` rows gain `exportResetAt`, `spentAtExport`, `resetSinceExport`, `restored`, plus top-level `resetSummary` and `cdnVersion`; `/api/storage` gains `cdnVersion`; `/api/health` gains `activityThresholds`, per-item `evidenceData`, `export-stale` moments and (30 Oct) the `combat-lines` item plus ok and info `everyone-feed` items; `/api/zone` gains `matched` and `guessed`; `/api/health` items of the export, vault-sizes, cdn and alt sources gain `files` in `views`. File ids for `/api/file/*` are `reports/<name>`, `app/capacity.json`, `cdn/v<ver>/<name>.json` or `logs/Chat-YY-MM-DD.log`, nothing else is served (`400 bad file id` / `404`); the chat-log health item lists `files` in `views` too. Field shapes are in `DESIGN.md` → Server contract.

Preview modes (browser only, never saved): `?shift=72`, `?sim=fresh|partiallog|party|stale|broken|nolog|noexport|loading|down`, `?theme=dark|daylight|auto`.
