The client's `Assembly-CSharp.dll` (UTF-16 user strings) still has the VIP panel keys `VIP_Reports_Items_JSON`, `VIP_Reports_Items_CSV`, `VIP_Reports_Character_JSON`, `VIP_Reports_Stored_Location`, the folder name `/Reports`, a `-reportdir` command-line option, the `api itemreport ` server command and `AutoExportCharacterOnLogout`; no string anywhere in the client mentions "player files". The wiki's Game updates page lists nothing newer than 3 Sep 2026 and no change to exports. So nothing moved: a missing storage export means none was taken (the 25 Oct chat log has 30 `Saved report` lines, all `Character_…`, none `_items_`).

**`Character_<Name>_<Server>.json`** (`Report: "CharacterSheet"`), overwritten on each export:
- `Character`, `ServerName`, `Timestamp` (UTC), `Race`, `MostRecentArea` (e.g. `AreaEltibule`)
- `Skills{name: {Level, BonusLevels, XpTowardNextLevel, XpNeededForNextLevel, Abilities[]}}`, where key `Unknown` is a catch-all ability list (skip it)
- `CurrentStats{}`: `MAX_HEALTH`, `MAX_INVENTORY_SIZE`, `NPC_MOD_MAXSALESVALUE` (sell *price* multiplier, NOT vendor cap), etc.
- `Currencies{}`: `GOLD` = Councils, plus GUILDCREDITS, DRUIDCREDITS, COMBAT_WISDOM, renown…
- `ActiveQuests[]`, `CompletedQuests[]`, `ActiveWorkOrders[]`, `CompletedWorkOrders[]`, `RecipeCompletions{recipe: count}`
- `NPCs{NPC_Key: {FavorLevel, Favor, CouncilsSpent, VendorResetTime?, PlayerNotes}}`
  - `CouncilsSpent` = councils that vendor has paid you since its last reset; `VendorResetTime` (UTC) when it resets. If reset time is past, treat spent as 0.

**Auto-export (official, game update 2026-10-21 "Halloween Update"):** the patch notes say: "There is now a checkbox in the VIP settings to automatically save the current character whenever you log out or switch areas." So the zone-change export is **by design**, part of the game's shared client logic; the notes mention no platform difference (Windows/Mac). Settings key: `AutoExportCharacterOnLogout` (name says logout, behaviour includes area switches). Source: Steam news for app 342940 (`api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid=342940`).
- Timing on this Mac: the `Saved report` line comes as you **leave** a zone, ~10–15 s before the next `Entering Area` line (also at `Logged Out`).
- Verified 2026-10-23 with the user: setting off (file updates immediately to `AutoExportCharacterOnLogout 0 0`) → three zone changes, no saves; back on → saves resume.
- Counted 2026-10-25 over the 23 to 25 Oct logs (`Saved report` lines): 33 / 34 / 53 character saves a day against 36 / 35 / 51 `Entering Area` lines, plus one at each logout and one 1 to 3 minutes after most logins. Storage (`_items_`) saves only when a button is pressed: 3 on 23 Oct, 0 on 24 Oct, 1 on 25 Oct (19:43, by hand). The `Character__Arisetsu.json` partial twin is written as a same-second pair and mostly mid-session (25 Oct: 00:13, 01:30, 15:28, 16:42, 17:17; none at the two logouts), so it is not a logout artefact; it is ignored either way. The VIP settings panel (screenshot 25 Oct) has only "Automatically Export on Logout" and the three buttons (Export Storage as Spreadsheet / as JSON, Export Character as JSON), and shows the Mac path `/Users/<name>/Library/Application Support/unity.Elder Game.Project Gorgon/Reports/`, which is `DEFAULT_GAME_DIR / "Reports"` in `server.py`.
- Trade-off: on = fresh vendor numbers at every zone change + chat spam + occasional partial copy at logout; off = manual exports only.
- Not caused by this app: the server only reads the game folder, and the Mac app has no input/Accessibility access.

**NPC vendor fields are new (same 2026-10-21 update):** raw `Favor`, `CouncilsSpent`, `VendorResetTime` and `PlayerNotes` per NPC were added to the character report then. Exports from before 21 Oct have none of them (e.g. Faechew's April export: 116 NPCs, 0 with `CouncilsSpent`), so councils-left can't be computed from them. Same update: "Fix favor-up unlocks reporting the wrong storage amounts".

**Known glitch:** an export done right before logging out produced `Character__Arisetsu.json` with `Character: "???"`, `Race: "Error"`, empty quests/recipes. Dashboard ignores `???` exports for vendor/storage and warns on the Character tab.

Within one vault only the last stack of a type is partial (Marna Empty Bottle 10×7+2), so the game evidently auto-stacks on deposit (inferred from data, not watched in game). No stack exceeds its `MaxStackSize`.

- Older exports also exist as `.csv`.

### `ChatLogs/Chat-YY-MM-DD.log` — the live source
Requires Settings → GUI → "Log All Chat". Format: `YY-MM-DD HH:MM:SS\t<message>`; continuation lines have no timestamp. Local time. A new file starts at midnight (sessions spanning midnight are split across files).

Useful patterns (regexes in `server.py`):
- `**** Logged In As Robchew. Server Arisetsu. Timezone Offset 02:00:00.` / `**** Logged Out`
- `**** Entering Area: Serbule`
  - Area names seen in the logs (10 to 24 Oct, plus April/May): Casino, Eltibule, Serbule, Povus Caves, Gazluk Caves, Kur Mountains, Kur Caves, Statehelm, Rahu, Mysterious Locale, Serbule Hills, Ilmari Desert, Fae Realm, Sun Vale, Vidaria, Beneath Eltibule, Rahu Sewers, Underneath Serbule, Guild Hall, Under Statehelm, Povus, Caves, Beneath Ilmari, Khyrulek's Crypt, Gazluk, Beneath Kur, Anagoge, Gazluk Keep, Dungeon. All map to `areas.json` keys (`FriendlyName` / `ShortFriendlyName`; Povus Caves, Fae Realm and Underneath Serbule to two keys each) except **`Khyrulek's Crypt`** (`26-04-30 10:45:23	******************** Entering Area: Khyrulek's Crypt`, 3 visits): no `areas.json` key, and its NPC Sir Arif sits under `AreaTomb1` with `AreaFriendlyName` "Serbule Crypt", so `/api/zone` answers `matched: false`. **`Caves`** (`26-04-30 19:46:13	******************** Entering Area: Caves`, after Anagoge; `26-10-20 22:05:50`, after Serbule Hills) and **`Dungeon`** (`26-05-02 22:57:33`) are shared short names: `areas.json` has one key each (`AreaSerbuleCaves` "Caves Under Serbule", `AreaMyconianCave` "Underneath Serbule"), so the match is a guess (`guessed: true`).
- `[Status] You earned 29 XP in Mycology.` / `… XP and reached level 60 in Mycology!`
- `[Status] Spider Leg x5 added to inventory.` (one line per stack; `26-10-20 23:48:58	[Status] Rough Phlogiston x30 added to inventory.` is one stack of 30, `26-10-20 23:46:16	[Status] Giant Mantis Claw added to inventory.` one of 1; over 143 login sessions the median was 33 stacks, 75th percentile 119)

No `[Status]` line exists for depositing or withdrawing; the only vault errors are `[Error] Error: That won't fit in storage!` and `[Error] Error: That item isn't in the vault.`, not used by any rule (trigger unverified in game).
- Councils lines (verified 24 Oct over 30 logs: `grep -h Councils Chat-*.log`; every other hit is player chat with lowercase "councils"). Four shapes, regexes `COUNCILS_*_RE` in `server.py`:

- Death tracker (verified 24 Oct over 30 logs; rules in `server.py` `CombatTracker`):
  - Attack lines have three shapes: `26-10-23 22:21:00	[Combat] Dread Pixie #279875: PixieSlash on Robchew! Dmg: 72 health, 71 armor.   - A FATALITY line on the character is not one death: mobs keep hitting the corpse (`Chat-26-10-11.log` 00:30:46, 00:30:58, 00:31:18 `Ratkin Miner #10923407: Pound on Robchew! … (FATALITY!)`, one death). Some FATALITY deaths print no Dying line (`Chat-26-10-11.log` 18:42:01, respawn in Mysterious Locale 38 s later). So a death = either signal, and the two merge within 120 s until the character acts, enters an area, logs in or out. `hits` counts FATALITY lines only: 60 of 90 Dying lines share the second with their FATALITY line, so the Dying line never counts as a corpse hit (`Chat-26-10-22.log` 22:29:17 is one death, hit once; `Chat-26-10-11.log` 00:30:46 is hit 3 times). The character's own attack in the same second as the death does not end it: the game writes a queued attack between the Dying line and its FATALITY line (`Chat-26-10-20.log` 20:10:19 `You earned 5 XP in Dying.`, then `Robchew: Dampen 8 on Hobgoblin Elite Troop…`, then `Hobgoblin Elite Assassin #16567803: Arrrrrrrrrow on Robchew (CRIT!) … (FATALITY!)`, one death), so an own attack ends a death only when it is more than 1 s after it (the real resurrect-and-die pair `Chat-26-10-12.log` 20:32:35 and 20:33:12, 37 s apart, stays two deaths). Dying XP seen: 5 (87 lines), 50, 100, and once `You earned 100 XP and reached level 23 in Dying!`. Dying stays in XP by skill: it is the game's own skill.
  - Not deaths: `[Status] You evaded death!` (a survived hit; counted as a close call). ## 3. Public CDN — `https://cdn.projectgorgon.com/v<N>/data/<file>.json`
- Version: `http://client.projectgorgon.com/fileversion.txt` (was **488**).
- **Needs a User-Agent header**; Python's default UA gets 403.
- Index of files: `https://cdn.projectgorgon.com/v<N>/data/index.html`

Used so far:
- **`npcs.json`**: `Name`, `AreaFriendlyName`, `Preferences[]` (gift likes), `Services[]`:
  - `Store`: `CapIncreases: ["Friends:10000:Armor,Weapon", …]`. Vendor cap = highest tier ≤ your favor; third field = item types bought.
  - `Storage`: `SpaceIncreases`; `Training`, `Consignment`, `Barter`, `InstallAugments`, `Stables`, `AnimalHusbandry`, `GuildQuests`
- **`storagevaults.json`**: per vault key (same key as NPC, e.g. `NPC_Kib`): `Levels{favor: slots}` | `NumSlots` | `SlotAttribute` (e.g. `MAX_CASINO_VAULT_SIZE`, not in exports) | `NumSlotsScriptAtomic` (community chests, 1–150); `RequirementDescription`, `Area`.
  - `NumSlots: 0` for Saddlebag, CouncilVault, `*AccountStorage_*`: size not available anywhere → manual entry (`capacity.json`).
- **`areas.json`**: `AreaCave1` → `FriendlyName` / `ShortFriendlyName`.
- **`items.json`** (used by `/api/consolidation` and `/api/icons`): keys `item_<TypeID>` (e.g. `item_1` = Empty Bottle); `MaxStackSize` on all 11,209 entries in v488 (the only stack-size field; `MaxOnVendor` is vendor stock, not a stack cap), `MaxCarryable` on 321 (e.g. Carnivine Tooth 7), `IconId`, `Keywords`.

Favor order: Despised, Hated, Disliked, Tolerated, Neutral, Comfortable, Friends, CloseFriends, BestFriends, LikeFamily, SoulMates.

**Verified:** vendor caps are unscaled. Kib stopped at 59,982/60,000, Otis 4,499/4,500, Ashk 39,890/40,000. The 1.22 `NPC_MOD_MAXSALESVALUE` boosts per-item price only.

Other CDN files of interest for future features: `items.json`, `recipes.json`, `skills.json` (XP tables), `quests.json`, `abilities.json`, `tsysclientinfo.json` (item powers), `sources_*.json`.
