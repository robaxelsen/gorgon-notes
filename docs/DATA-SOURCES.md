**`Character_<Name>_<Server>.json`** (`Report: "CharacterSheet"`), overwritten on each export:
- `Character`, `ServerName`, `Timestamp` (UTC), `Race`, `MostRecentArea` (e.g. `AreaEltibule`)
- `Skills{name: {Level, BonusLevels, XpTowardNextLevel, XpNeededForNextLevel, Abilities[]}}`, where key `Unknown` is a catch-all ability list (skip it)
- `CurrentStats{}`: `MAX_HEALTH`, `MAX_INVENTORY_SIZE`, `NPC_MOD_MAXSALESVALUE` (scales each vendor's **cap per item**, not the weekly pool and not the item's Value; see §4b), etc.
- `Currencies{}`: `GOLD` = Councils, plus GUILDCREDITS, DRUIDCREDITS, COMBAT_WISDOM, renown…
- `ActiveQuests[]`, `CompletedQuests[]`, `ActiveWorkOrders[]`, `CompletedWorkOrders[]`, `RecipeCompletions{recipe: count}`
- `NPCs{NPC_Key: {FavorLevel, Favor, CouncilsSpent, VendorResetTime?, PlayerNotes}}`
  - `CouncilsSpent` = councils that vendor has paid you since its last reset; `VendorResetTime` (UTC) when it resets. If reset time is past, treat spent as 0.

### `ChatLogs/Chat-YY-MM-DD.log` — the live source
Requires Settings → V.I.P. → "Save Chat Logs" (user, 27 Oct 2026: the GUI tab was the wrong place; the Settings window's V.I.P. tab holds "Combat Logging" with per-category "Log when…" dropdowns ("Log File Only (if enabled)") and "Log non-damaging abilities", and its hint says "Remember to enable 'Save Chat Logs' if you want your combat logs to be written to a file!"). **Combat Logging verified 30 Oct** (user's screenshot of the whole section, matched to `GorgonSettings.txt`): seven "Log when…" dropdowns, each Off / "Chat Window (and log file if enabled)" / "Log File Only (if enabled)", stored as `combatLog_<Row>` = 0 / 1 / 2 (`MeAttackEnemy`, `PetAttackEnemy`, `EnemyAttackMe`, `EnemyAttackPet`, `MeIndirectlyDamaged`, `PetIndirectlyDamaged`, `EnemyIndirectlyDamaged`, in the window's order), then a "Log non-damaging abilities" checkbox (`LogNonAttacks` 1 = ticked). `VIP_CombatLogging` was 1 with the section expanded. The same V.I.P. tab shows the Reports folder path with an Open Folder button above the section. The "Save Chat Logs" toggle itself was not in this screenshot. Format: `YY-MM-DD HH:MM:SS\t<message>`; continuation lines have no timestamp. Local time. A new file starts at midnight, with no login or area line when you were playing then (sessions spanning midnight are split across files: user, 28 Oct 2026, an egg run from 23:45 to 00:17 showed only its post-midnight fights as "Unknown area 00:00 to 00:18"). The DPS tracker feeds the previous day's log first (`previous_chatlog`, `DpsTracker.begin_log`, `day_boundary`), so such a run is one session with its area.

## 3. Public CDN — `https://cdn.projectgorgon.com/v<N>/data/<file>.json`
- Version: `http://client.projectgorgon.com/fileversion.txt` (was **488**).
- **Needs a User-Agent header**; Python's default UA gets 403.
- Index of files: `https://cdn.projectgorgon.com/v<N>/data/index.html`

Used so far:
- **`npcs.json`**: `Name`, `AreaFriendlyName`, `Preferences[]` (gift likes), `Services[]`:
  - `Store`: `CapIncreases: ["Friends:10000:Armor,Weapon", …]`. Vendor cap = highest tier ≤ your favor; third field = item types bought.
  - `Storage`: `SpaceIncreases`; `Training`, `Consignment`, `Barter`, `InstallAugments`, `Stables`, `AnimalHusbandry`, `GuildQuests`
- **`storagevaults.json`**: per vault key (same key as NPC, e.g. `NPC_Kib`): `Levels{favor: slots}` | `NumSlots` | `SlotAttribute` (e.g. `MAX_CASINO_VAULT_SIZE`, not in exports) | `NumSlotsScriptAtomic` (community chests, 1–150); `RequirementDescription`, `Area`.
  - `NumSlots: 0` for Saddlebag, CouncilVault, `*AccountStorage_*`: size not available anywhere → manual entry (`capacity.json`).
- **`areas.json`**: `AreaCave1` → `FriendlyName` / `ShortFriendlyName`.
- **`items.json`** (used by `/api/consolidation` and `/api/icons`): keys `item_<TypeID>` (e.g. `item_1` = Empty Bottle); `MaxStackSize` on all 11,209 entries in v488 (the only stack-size field; `MaxOnVendor` is vendor stock, not a stack cap), `MaxCarryable` on 321 (e.g. Carnivine Tooth 7), `IconId`, `Keywords`.

## 4. Project: Gorgon wiki — Teleportation Machine codes (verified 2026-10-26)

The Teleportation Machine codes are **not in the game data**: they are a player-maintained list on the wiki page https://wiki.projectgorgon.com/wiki/Teleportation_Machine. `server.py` reads it as wikitext through the MediaWiki API (`GET https://wiki.projectgorgon.com/api.php?action=parse&page=Teleportation_Machine&prop=wikitext|revid&format=json`, about 8 KB; **send a User-Agent**, `fetch()` does) and parses it with regexes (`parse_teleport_wikitext`), for `GET /api/teleports` and the Teleports tab.

Structure under the heading `=== Teleportation Machine Codes ===`, inside a `{{Spoiler|Destination List| … }}` template:
- `; '''Numbers are confirmed as of March 28, 2025''' …` is the page's own freshness line (parsed into `confirmedAsOf`, `2025-03-28`); the page says most codes rotate whenever a zone or dungeon is added, so this date is what "fresh" means for these numbers, not the fetch time.
- `; [[Zone]]` starts a zone (14 on 26 Oct 2026, revision 282545: Anagoge Island, Serbule Hills, Serbule, Sun Vale, Eltibule, Red Wing Casino, Kur Mountains, Ilmari, Rahu, Gazluk, Povus, Vidaria, Statehelm, Fae Realm). Text after the link is a zone note (`; [[Fae Realm]] - "Alharth tp machine can't send you to different planes." - Citan`, no codes). A `;` heading without a link (none on the page today) is parsed as its own zone, never folded into the zone before it; the confirmed-as-of line ends the zone above it.
- `: Landmark text.` a landmark (may hold `[[links]]`, `[[link|text]]`, a trailing period, an HTML comment); 108 on 26 Oct.
- `:: 0055, 3049` its codes: four digits, comma separated, one line reads `:: 0056  0091 (inside)` (two codes, the words kept as the landmark's note) and one `::3824` (no space); 214 codes on 26 Oct.

Facts from the page (26 Oct 2026): the one working machine is in Windy View Cave (Gazluk); it needs Teleportation level 25 and 2 Aquamarine per trip; it cannot reach the Fae Realm; its in-game message says the coordinates are relative to the sender. Zone names differ from the chat log's (`Ilmari Desert` vs `Ilmari`, `Anagoge` vs `Anagoge Island`, `Casino` vs `Red Wing Casino`), which the page matches by word prefix (`tpHereZone` in `app.js`).

Cache: `cache/wiki/teleport-codes.json` (the parsed zones plus the raw wikitext, `fetchedAt`, `revid`), beside the CDN cache; re-fetched at most once a day or on `?refresh=1`; while the wiki is unreachable the cached copy answers with `error` set (the footer and margin say so).

## 5. Statehelm gifts (Prodigy Potential), checked 27 Oct 2026

- **The rule** (wiki, Prodigy Potential page): most Prodigy Potential trainers are in Statehelm, they unlock it at Close Friends, and "the weekly limit of 5 gifts per week" slows that down; Statehelm trainers take Councils or Statehelm Renown for the unlock. Neither the wiki nor the game data says when the week resets; the weekly buff runs Monday 00:00 to Sunday 23:59 per the patch notes. **Verified 28 Oct 2026** from the game's Give Gift dialog (screenshot, Parella): "[Note: Statehelm townsfolk are more sophisticated than villagers elsewhere. It would be uncouth to receive too many gifts per week -- Statehelm villagers value quality over quantity. Parella will accept up to **5** gifts per calendar week and has received **0** so far this week. (The week resets on Monday EDT.)]" So the week turns Monday 00:00 US Eastern (`WEEK_RESET_TZ` in server.py; glogger's Monday 00:00 UTC is off by four or five hours), and Parella's gift of Monday 26 Oct 01:30 local (Sunday 20:30 Eastern) was last week's, as the app now shows (0 of 5 on both sides). The dialog is the one place the game states the count; it is not written to the chat log (no line of it in any log), so the chat-log count and the − / + override stay. The Windows embeddable Python has no tz database, so `_USEastern` carries the US DST rule as a fallback (checked against zoneinfo on the 2025 to 2027 DST edges).
- **What each trainer likes:** `npcs.json` `Preferences[]` (`Desire` Love / Like / Dislike / Hate, `Name` such as "Epic Swords", `Keywords[]`, `Pref` multiplier, sometimes `Favor`, the tier from which the preference counts). Keyword forms seen on the 44 Statehelm trainers: plain item keywords (`Sword`, `Instrument`, `Druidic`, `Phlogiston`), `MinRarity:Rare|Epic`, `SkillPrereq:<skill>` (the item's `SkillReqs` names that skill), `!Stock` (the item lacks the `Stock` keyword), `Special:MastercraftedOrForetold` (not judged: the export has no such flag). Items in the storage export carry `Rarity` only when it isn't Common. Item keywords in `items.json` can carry a value suffix (`Druidic=3`, `Phlogiston=24`); the app compares the part before `=` (`item_keywords`), so `Druidic` matches 3 items, `Phlogiston` 10, `FishPetPiece` 36, `RabbitFuel` 2.
- **Trainers:** every Statehelm NPC with a `Training` service (44 in v490, incl. three in Statehelm Caves: Fuzzlebun, Hamilton, Smoke Tail). `Services[].Unlocks` lists the favor tiers that open more training. Readable skill names from `skills.json` `Name` (null for some, e.g. Sword: the code split on capitals is used).
- **Your side:** favor per NPC in the character export (`NPCs{key: {FavorLevel, Favor}}`); the gift count is in nothing the game writes out (no export field, no "You gave" chat line, nothing at the cap). The chat log writes `[Status] You gained 44.5 favor with Sir Abbley` per gift (four in 40 s on 12 Oct: 44.5, 43.5, 42.5, 40), and the same line for a quest turn-in (Ser Hackley: 50 favor and "Council Certificate added to inventory" in the same second) and for small talk. The app counts the lines in Statehelm since the week started and leaves out those with a loot line in the same second.
